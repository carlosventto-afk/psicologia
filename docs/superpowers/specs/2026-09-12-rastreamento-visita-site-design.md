# Rastreamento de visita ao site (item 24, parte 2) — design

Status: aprovado para implementação
Data: 2026-09-12

Pedido do usuário: registrar cada visita aos domínios públicos do
PsiAgente e o fluxo completo até a conversão/compra, como base de dados
pro CRM de vendas (item 24, partes 3 e 4, ainda não iniciadas). Parte 1
do item 24 (notificação por e-mail ao ADM) já está implementada
(`e37d39f`).

## Decisões já tomadas com o usuário

- Rastreamento próprio (não ferramenta de terceiro como GA/Plausible) —
  dado fica só nosso, sem depender de aceite de cookie de propaganda.
- Granularidade: **cada pageview**, não só a página de entrada.
- IP guardado só como **hash SHA-256**, nunca em texto puro.

## O que já existe (não faz parte desta entrega)

- `web/proxy.js` — middleware que roda em toda requisição de todo
  domínio/subdomínio, reescreve `comece.`/`busca.`/`blog.` pros
  respectivos segmentos internos, redireciona domínio antigo, e chama
  `web/lib/supabase/proxy.js`'s `updateSession()` pro resto.
- `web/lib/supabase/admin.js` (`createAdminClient()`) — client
  service-role, fetch-based (`@supabase/supabase-js`), funciona em
  qualquer runtime (Edge ou Node) — usado aqui sem modificação.
- `web/lib/actions/auth.js` (`cadastrar()`) — onde a conta é criada;
  ganha a leitura do cookie de sessão anônima.
- Padrão de tabela sem RLS (só `service_role` lê/escreve, sem
  policies) já usado em `EventoAssinatura`/`EnvioAutomaticoCarneLeao` —
  reaproveitado aqui.

## Escopo de captura

Rastreio:
- Os 3 subdomínios públicos inteiros: `comece.`, `busca.`, `blog.`
  (toda página ali é conteúdo público de marketing).
- No domínio principal, só o funil pré-login: `/`, `/login`,
  `/cadastro`, `/completar-cadastro`, `/esqueci-senha`.

Não rastreio nada do painel logado (`/agenda`, `/painel`,
`/financeiro` etc.) — não é uso do produto, é funil de venda, então
para no que vem antes da conversão. A lista de paths do domínio
principal fica como uma constante `PATHS_FUNIL` em `web/proxy.js`,
checada por igualdade exata (não por prefixo — mesmo cuidado já
documentado pra `/` no middleware de sessão).

## Cookie de sessão anônima

`pv_id` — UUID (`crypto.randomUUID()`, disponível tanto em Edge quanto
Node), `httpOnly`, `sameSite: "lax"`, `maxAge` de 1 ano, `path: "/"`.
Gerado na primeira visita rastreável, se ainda não existir; reenviado
como está nas visitas seguintes. Como `web/proxy.js` tem vários pontos
de retorno (redirect de domínio antigo, rewrite de cada subdomínio,
`updateSession()`), um helper local `comCookieVisitante(response,
sessaoId, novo)` envolve cada `return` existente pra garantir que o
cookie sempre seja setado quando novo, independente de qual branch
respondeu.

## Schema

```sql
create table "VisitaPagina" (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  sessao_id uuid not null,
  host text not null,
  path text not null,
  referrer text,
  utm_source text,
  utm_medium text,
  utm_campaign text,
  utm_term text,
  utm_content text,
  ip_hash text,
  user_agent text
);

create index visitapagina_sessao_id_idx on "VisitaPagina" (sessao_id);

alter table "VisitaPagina" enable row level security;
-- sem nenhuma policy: só service_role (que ignora RLS) lê/escreve
-- aqui, mesmo padrão já usado em "EventoAssinatura".
```

`Usuarios` ganha uma coluna nova:

```sql
alter table "Usuarios" add column visitante_sessao_id uuid;
```

Sem FK entre as duas — `sessao_id` não é chave única em
`VisitaPagina` (várias linhas por sessão), então o link é feito só por
igualdade de valor na hora da consulta (`Usuarios.visitante_sessao_id =
"VisitaPagina".sessao_id`), não por constraint.

## Captura em `web/proxy.js`

Pra cada requisição que bate no escopo acima:
1. Ler `pv_id` do cookie; se ausente, gerar um novo (`crypto.randomUUID()`).
2. Extrair: host (`request.headers.get("host")`), path
   (`request.nextUrl.pathname`), referrer (`request.headers.get("referer")`),
   UTMs (`request.nextUrl.searchParams.get("utm_*")`), IP
   (primeiro valor de `x-forwarded-for`, header que o Traefik desta VPS
   já preenche — ver `docs/superpowers/specs` do item 7/NFS-e pro mesmo
   padrão de reverse proxy), user-agent
   (`request.headers.get("user-agent")`).
3. Hash do IP com `crypto.subtle.digest("SHA-256", ...)` (Web Crypto —
   funciona em Edge e em Node 18+, ao contrário do módulo `crypto` do
   Node puro, que não existe em Edge runtime).
4. Filtrar navegação real: só `method === "GET"` e sem o header
   `Next-Router-Prefetch` (é esse header, não o header `RSC`, que
   distingue prefetch especulativo de navegação de verdade — uma
   navegação real entre páginas via `<Link>` client-side também chama
   com `RSC: 1`, e excluir por esse header contaria só carregamento de
   documento completo, perdendo a maioria dos cliques dentro do site).
5. Insert em `VisitaPagina` via `createAdminClient()` — **aguardado**
   (não fire-and-forget via `after()`): é um insert simples numa tabela
   sem índice pesado, custo de latência aceitável, e evita depender de
   `after()` funcionar de forma confiável dentro de middleware num
   deploy self-hosted (Node standalone) sem verificar antes — YAGNI,
   resolve com o jeito mais simples que funciona garantido.
6. Erro no insert nunca bloqueia a navegação (`try/catch` silencioso,
   só loga) — rastreamento não pode derrubar o site.

Esse bloco entra no topo de `proxy()`, antes de qualquer branch de
host, e todo `return` existente passa a envolver a resposta em
`comCookieVisitante(...)`.

## Link até o cadastro

Em `cadastrar()` (`web/lib/actions/auth.js`): lê o cookie `pv_id` via
`cookies()` (Server Action já roda no contexto de request) e, se
presente, inclui `visitante_sessao_id: pv_id` no insert de `Usuarios`
que já existe. Não requer nenhuma consulta nova — só um campo extra no
insert que já acontece.

## Consulta do funil (não faz parte desta entrega — só documentado pra
a parte 3 saber onde buscar depois)

```sql
select v.*
from "VisitaPagina" v
join "Usuarios" u on u.visitante_sessao_id = v.sessao_id
where u.id = :usuario_id
order by v.created_at;
```

## Testes

Sem framework automatizado (convenção do projeto). Verificação por
camadas, com dado descartável:
1. Migration aplicada direto contra produção (mesmo padrão de sempre —
   script `pg` com `SUPABASE_DB_PASSWORD`), confirmar coluna/tabela.
2. Build + start local, navegar por `/`, `/comece` (via `Host` header
   simulado ou hosts file), confirmar cookie `pv_id` persiste entre
   navegações e que cada pageview grava uma linha nova em
   `VisitaPagina` (SQL direto).
3. Confirmar que um prefetch do Next (link com `<Link>` no viewport)
   **não** grava linha duplicada — só a navegação real.
4. Cadastro de teste descartável com o cookie `pv_id` presente,
   confirmar que `Usuarios.visitante_sessao_id` foi preenchido com o
   mesmo valor, e que o JOIN documentado acima traz as páginas vistas
   antes do cadastro. Apagar o dado de teste ao final.
5. Confirmar que `/agenda`/`/painel` (autenticado) **não** grava linha
   nenhuma.
